## 3. Структура базы данных

Создан файл `data/visited_places.sqlite3`. В `sql/schema.sql` определены
четыре таблицы с целочисленными первичными ключами `id`:

| Таблица | Основные данные и связи |
| --- | --- |
| `users` | Логин, имя, email, хеш пароля, признаки администратора и активности |
| `places` | Название, город, страна, категория, адрес фотографии |
| `trips` | Название, даты начала и окончания, внешний ключ `place_id` |
| `visits` | Внешние ключи `user_id`, `trip_id`, дата и время, оценка, заметка |

Связи: пользователь 1:N посещения, поездка 1:N посещения, место 1:N поездки.
У поездки нет пользователя; место посещения определяется через поездку.
Текст хранится как `TEXT`, даты - в ISO-формате. Оценка допускает `NULL`
или значение 1-5. Предусмотрены `UNIQUE`, `CHECK`, внешние ключи и индексы.
`ON DELETE RESTRICT` защищает связанные места и поездки от удаления.

## 4. Перенос данных и подключение

`db/database.py` открывает соединение через `sqlite3.connect()`, включает
`PRAGMA foreign_keys = ON` и `sqlite3.Row`. Функции `fetch_all`, `fetch_one`
и `execute` получают результаты по именам полей, сохраняют изменения
через `commit()` и закрывают соединение. Пользовательские значения передаются
параметрами `?`, а не подставляются в текст SQL.

`db/import_json.py` переносит `users.json`, `places.json`, `trips.json`
и `visits.json` через `executemany()` в одной транзакции. Ошибка вызывает
откат; повторный импорт в заполненную базу пропускается. Исходный набор:
3 пользователя, 6 мест, 6 поездок, 6 посещений. JSON сохранены. Из прежней
веб-базы отдельно перенесены записи и существующие хеши паролей; файл
`data/web.sqlite3` оставлен нетронутым как резервная копия.

## 5. Запросы и страницы проекта

В `sql/queries.sql` сохранены и проверены 12 запросов: списки мест и поездок;
поиск по городу; фильтр посещений по датам; журнал с объединением четырех
таблиц; сведения о поездке; непосещенные места через `NOT EXISTS`; количество
посещений, уникальных мест и средняя оценка; число объектов каталога;
группировка посещений по местам с `HAVING`; группировка по странам;
поездки, период которых включает выбранную дату. Используются `SELECT`,
`WHERE`, `JOIN`, `COUNT`, `AVG`, `GROUP BY`, `ORDER BY`, `LIMIT`, `OFFSET`.

Представления `visited_places/views.py` получают SQL-результаты и передают
их в шаблоны через `render()`. Работают `/places/`, `/trips/`, `/visits/`,
`/statistics/` и отдельные страницы объектов. Есть поиск, фильтры и пагинация
по 12 записей. Аналог поиска свободных помещений из примера Roomly адаптирован
к своей теме: поиск непосещенных мест и поездок на выбранную дату.

Сложный API и модальные окна заменены обычными HTML-формами. Сохранены
регистрация, вход и редактирование. Посещения доступны владельцу, изменение
общих мест и поездок - администратору. Пароли хешируются, POST-формы защищены
CSRF. README обновлен. Подготовка: `manage.py init_db`; запуск:
`manage.py runserver 127.0.0.1:8002`. Консольная версия и ее отдельная база сохранены.
