Visited Places - система учета посещенных мест на Django и SQLite.
Основной интерфейс работает в браузере: личный журнал, каталог мест,
общие поездки, оценки, заметки и статистика. Страницы обращаются к JSON API.
Консольная версия из практических №1-3 сохранена отдельно.

## Быстрый запуск веб-версии

Откройте папку `visited-places` в VS Code и терминал PowerShell.
Активация окружения и команда `django-admin` не нужны.
При первом запуске выполните:

```powershell
cd "$HOME\Desktop\visited-places"
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe manage.py migrate
.\venv\Scripts\python.exe manage.py import_journal
.\venv\Scripts\python.exe manage.py setup_demo
.\venv\Scripts\python.exe manage.py collectstatic --noinput
.\venv\Scripts\python.exe serve.py
```

Откройте http://127.0.0.1:8000/. Команда `setup_demo` показывает логин `gleb`
и случайный пароль при первом создании локального учебного аккаунта.
Повторный вызов не меняет существующий пароль. Команда доступна только
в режиме разработки. Другой аккаунт можно создать через регистрацию.
Импортированным пользователям пароль автоматически не назначается.

Для уже подготовленного проекта достаточно:

```powershell
.\venv\Scripts\python.exe serve.py
```

Остановка сервера: `Ctrl+C`. Если порт занят:

```powershell
.\venv\Scripts\python.exe serve.py --port 8001
```

Для разработки с автоматической перезагрузкой:

```powershell
.\venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

В VS Code для отладки выберите `Django: Visited Places`.

## Веб-приложение

- Регистрация, вход, выход и редактирование имени/email.
- Общий каталог мест и поездок; создавать записи может любой вошедший
  пользователь, изменять и удалять общие записи может только администратор.
- Личные посещения: создание, просмотр, изменение даты, поездки, оценки
  и заметки, удаление с подтверждением. Чужие отметки недоступны в API.
- Поиск, фильтры по поездке и датам, пагинация, персональная статистика.
- Страницы отдельного места, поездки и своей отметки с навигацией между ними.
- Административный интерфейс: http://127.0.0.1:8000/admin/.

Связи сохранены: `User -> Visit -> Trip -> Place`. У `Trip` нет `user`,
у `Visit` нет `place`; место определяется по поездке. Дата посещения должна
попадать в период поездки, оценка необязательна или равна 1-5. Нельзя удалить
место с поездками или поездку с посещениями. Изменение дат поездки не должно
исключать уже сохраненные посещения.

источники и лицензии перечислены в `images/credits.json`.

### Безопасность и размещение

По умолчанию сервер доступен только на этом компьютере. Пароли хешируются
Django, изменяющие запросы требуют CSRF-токен, владелец посещения определяется
из сессии. После 10 неудачных входов для пары IP/логин действует блокировка
на пять минут. Сессионные cookies HttpOnly/SameSite; данные форм проверяются
на сервере, SQL выполняется через ORM, заметки отображаются как текст.

Для внешнего размещения нужны собственный `DJANGO_SECRET_KEY`,
`DJANGO_DEBUG=0`, список `DJANGO_ALLOWED_HOSTS` и HTTPS. В этом режиме
включаются Secure cookies, перенаправление на HTTPS и HSTS. Перед запуском
нужно настроить доверенный HTTPS-прокси/WSGI-схему, выполнить миграции,
`collectstatic` и `manage.py check --deploy`. Учебный аккаунт не создается
в production; администратора создают через `manage.py createsuperuser`.
Внешнее размещение и HTTPS в локальной установке не выполняются.

SQLite не шифруется самим приложением: доступ к файлам БД и резервным копиям
ограничивается средствами ОС; для чувствительных данных нужны шифрование
диска/резервных копий и HTTPS. Перед обновлением делайте резервную копию
`data/web.sqlite3` при остановленном сервере. SQLite и локальный кеш рассчитаны
на небольшое приложение с одним процессом; для нескольких серверов потребуется
общий кеш и серверная СУБД.

## Консольная версия

Visited Places - рабочее консольное приложение на Python для журнала путешествий. Проект
помогает хранить пользователей, места, поездки и отметки о посещении, а также
искать места и считать персональную статистику путешествий. Операции доступны
через интерактивное меню, изменения сохраняются в SQLite между запусками.

Python-пакет приложения: `visited_places`.

Каталог проекта: `visited-places`.

## Предметная область

Предметная область проекта - учет посещенных мест. Пользователь может вести
личный журнал поездок, добавлять посещенные локации, ставить оценку, оставлять
заметку и просматривать статистику по городам, странам, местам и поездкам.

## Основные сущности

- `User` - пользователь журнала: `id`, `name`, `email`.
- `Place` - место: `id`, `name`, `city`, `country`, `category`.
- `Trip` - общая поездка к одному месту: `id`, `place`, `name`, `start_date`,
  `end_date`. Формат дат: `YYYY-MM-DD`.
- `Visit` - отметка о посещении: `id`, `user`, `visited_at`,
  `rating`, `note`, `trip`. Формат даты и времени: `YYYY-MM-DD HH:MM`.

Оценка `rating` может быть целым числом от 1 до 5 или `None`, если пользователь
не поставил оценку. Связи при сериализации сохраняются через идентификаторы:
`user_id`, `place_id`, `trip_id`.

У `Trip` нет пользователя; `place_id` хранится только в поездке. У `Visit`
нет отдельного места: оно определяется через `visit.trip.place`. Поездка
обязательна для посещения. Разные пользователи могут отмечать одну поездку,
но история и статистика каждого рассчитываются только по его отметкам.

## Основная логика

Класс `TravelJournal` в `visited_places/service.py` хранит коллекции
пользователей, мест, поездок и отметок. В сервисном слое предусмотрены методы:

- `add_user(name, email)`;
- `update_user(user_id, *, name, email)`;
- `add_place(name, city, country, category)`;
- `update_place(place_id, *, name, city, country, category)`;
- `add_trip(place_id, name, start_date, end_date)`;
- `update_trip(trip_id, *, name, start_date, end_date, place_id=None)`;
- `remove_trip(trip_id)`;
- `add_visit(user_id, trip_id, visited_at, rating=None, note='')`;
- `update_visit(user_id, visit_id, *, rating, note, visited_at=None, trip_id=None)`;
- `remove_visit(user_id, visit_id)`;
- `list_visits(user_id, trip_id=None)`.

При изменении посещения пропущенные `visited_at` и `trip_id` сохраняют текущие
значения. Снять обязательную связь с поездкой нельзя. Место меняется у самой
поездки или выбором другой поездки для посещения. Все поля проверяются до изменения
объекта, включая уникальность отметки. Изменение профиля и места сохраняет
идентификаторы и существующие связи с поездками и посещениями.

При операциях проверяются внешние ключи и принадлежность отметки пользователю,
попадание отметки в даты поездки, корректность рейтинга и отсутствие дублей по
комбинации `user_id`, `trip_id`, `visited_at`.

При изменении поездки проверяются место и даты всех связанных отметок:
нельзя сузить диапазон так, чтобы существующее посещение оказалось за его
пределами. Удаление поездки с отметками запрещено: сначала нужно удалить эти
отметки или перенести их в другую подходящую поездку. Общие поездки доступны
всем профилям; выбранный пользователь ограничивает только операции с отметками.

Дополнительные функции:

- `find_places(places, query)` - поиск мест по названию, городу, стране или
  категории: совпадение по фрагменту, пустой запрос возвращает весь каталог;
- `sort_places_by_name(places)` - сортировка мест по названию;
- `build_travel_statistics(visits, user_id=None)` - статистика по выбранному
  пользователю или по всем отметкам.

Статистика возвращает поля `visits`, `visited_places`, `cities`, `countries`,
`trips`, `average_rating`. Средняя оценка считается только по отметкам, где
оценка указана.

## Хранение данных

Основное хранилище приложения - SQLite-файл `data/journal.sqlite3`.
`JournalDatabase(path)` в `visited_places/database.py` предоставляет свойство
`exists`, методы `initialize(journal)`, `load()` и `save(journal)`.
Инициализация создает базу по `database/schema.sql` с `PRAGMA user_version = 2`
и записывает начальный журнал. Сохранение четырех коллекций выполняется
транзакционно.

База версии 1 автоматически переносится в версию 2 при загрузке. Перед
изменением создается файл `journal.v1-backup-<идентификатор>.sqlite3` рядом с
рабочей базой. Если старая поездка включала несколько мест, она разделяется
на поездки по местам; все отметки, пользователи, места, даты, оценки и заметки
сохраняются. Для старой отметки без поездки создается однодневная поездка.
При ошибке перенос откатывается. Если старая поездка не содержит отметок,
определить ее место нельзя: перенос прекращается без удаления данных.

При запуске `main.py` действует следующий порядок:

1. Если база уже существует, журнал загружается только из SQLite. JSON-файлы
   не заменяют сохраненные пользователем данные.
2. Если базы нет и есть все четыре JSON-файла, они используются как начальные
   данные для создания базы.
3. Если нет ни одного из четырех JSON-файлов, создается пустая база, а приложение
   предлагает ввести первого пользователя.
4. Если часть JSON-файлов отсутствует, запуск завершается с ошибкой данных.
   Неполный набор не восстанавливается автоматически.

Перед изменением приложение создает `deepcopy` рабочего журнала, применяет
операцию к копии и вызывает `JournalDatabase.save`. Рабочее состояние заменяется
копией только после успешного сохранения. При ошибке ввода или сохранения
показывается сообщение и снова открывается меню; неуспешная операция не меняет
рабочий журнал.

Приложение рассчитано на один экземпляр CLI для одной базы. Одновременная работа
нескольких сеансов с общим SQLite-файлом не поддерживается: полный снимок
журнала не обеспечивает согласование конкурентных изменений.

JSON остается дополнительным форматом для начальных данных и программного
импорта/экспорта через функции `visited_places/storage.py`:

- `load_json(path)` и `save_json(path, data)`;
- `load_users(path)` и `save_users(path, users)`;
- `load_places(path)` и `save_places(path, places)`;
- `load_trips(path, places)` и `save_trips(path, trips)`;
- `load_visits(path, users, trips)` и `save_visits(path, visits)`;
- `load_journal(directory)` и `save_journal(directory, journal)`.

`load_journal` также читает старый JSON-набор и преобразует его в памяти,
не перезаписывая исходные файлы. Экспорт использует только новую модель.

Схема содержит четыре таблицы: `users`, `places`, `trips`, `visits`.
В DDL заданы внешние ключи, уникальные ограничения, проверки канонических дат,
проверка рейтинга от 1 до 5, индексы для частых запросов и триггеры для
согласованности поездок и отметок.

Особенность SQLite: стандартный `COLLATE NOCASE` хорошо работает для ASCII, но
не является полноценной заменой `casefold()` для кириллицы. В Python-сервисе
сравнение email и мест выполняется через `casefold()`. В веб-версии для каталога
мест используются отдельные нормализованные ключи, заполняемые Django-моделью.

## Интерактивное меню

`ConsoleApplication(journal, database)` в `visited_places/cli.py` запускает
цикл меню методом `run() -> int`. При запуске выбирается первый пользователь
журнала; в пустой базе сначала предлагается создать пользователя.

| Пункт | Операция |
| --- | --- |
| 0 | Выход |
| 1 | Все посещения выбранного пользователя, без дополнительного ввода |
| 2 | Весь каталог мест, без дополнительного ввода |
| 3 | Общий список поездок |
| 4 | Добавить место |
| 5 | Добавить поездку |
| 6 | Добавить посещение |
| 7 | Изменить дату, поездку, оценку и заметку посещения |
| 8 | Удалить отметку с подтверждением |
| 9 | Статистика выбранного пользователя |
| 10 | Выбрать пользователя |
| 11 | Добавить пользователя |
| 12 | Изменить место, название и даты поездки |
| 13 | Удалить неиспользуемую поездку с подтверждением |
| 14 | Поиск мест |
| 15 | История посещений по выбранной поездке |
| 16 | Изменить название, город, страну и категорию места |
| 17 | Изменить имя и email выбранного профиля |
| м | Главное меню |

Пункты `1`, `2` и `3` сразу выводят списки или сообщение об отсутствии записей.
После результата длинное меню не повторяется: оно доступно по команде `м`.
В строке следующей команды указано имя выбранного пользователя.
Поиск (`14`) запрашивает строку; пустой запрос показывает все места. Фильтр
истории (`15`) сначала показывает поездки и запрашивает ID; пустой ввод
показывает все посещения выбранного пользователя.
При добавлении поездки выбирается место; при добавлении посещения выбирается
обязательная поездка. Оценка посещения необязательна.
При редактировании посещения (`7`) пустой ввод сохраняет текущее значение поля.
`0` в поле оценки убирает оценку; поездку оставить без связи нельзя;
`-` очищает заметку. В редактировании поездки (`12`), места (`16`) и профиля
(`17`) пустой ввод также сохраняет текущее значение. Для подтверждения удаления принимаются
`д`, `да`, `y`, `yes`; любой другой ответ отменяет удаление.
После успешного редактирования выводится запись с сохраненными значениями.

Выбор пользователя переключает локальный профиль и не является входом в
учетную запись: паролей и подтверждения личности нет, любой оператор терминала
может выбрать любой профиль. Для входа с паролем и сессией используйте
веб-версию. EOF и `Ctrl+C` завершают приложение без трассировки ошибки.
После успешного добавления пользователя его профиль выбирается автоматически.

## Требования

- Python 3.10 или новее;
- зависимости для тестов и линтинга из `requirements.txt`;
- SQLite через стандартный модуль Python `sqlite3`, без отдельного сервера БД.

## Запуск

```powershell
cd "$HOME\Desktop\visited-places"
pip install -r requirements.txt
python main.py
```

После загрузки базы появляется меню с выбранным пользователем. В новом пустом
каталоге данных перед меню запрашиваются имя и email первого пользователя.
Путь к данным по умолчанию определяется относительно `main.py`, а не текущего
каталога терминала.
В VS Code используйте терминал или конфигурацию `Python: Visited Places (console)`.
Для расширения Code Runner включен запуск в терминале, поскольку панели
Output и Debug Console не подходят для интерактивного ввода через `input()`.

Для отдельного журнала укажите другой каталог:

```powershell
python main.py --data-dir .\local-data
```

В нем создается `journal.sqlite3`. Если в каталоге отсутствуют все четыре
начальных JSON-файла, журнал начинается пустым. Повторный запуск с тем же
`--data-dir` продолжает работу с этой базой.

## Пример работы

1. Запустите приложение с `--data-dir .\local-data`. Для нового пустого журнала
   введите имя и email пользователя, например `Анна` и `anna@example.com`.
2. Выберите `4` и добавьте место: `Парк Победы`, `Калининград`, `Россия`, `парк`.
3. Выберите `5`, укажите ID созданного места и создайте поездку `Калининград` с датами `2026-10-06` и
   `2026-10-08`.
4. Выберите `6` и введите ID поездки, время `2026-10-06 12:00`,
   оценку `4` и заметку. Идентификаторы можно посмотреть
   в каталоге (`2`) и списке поездок (`3`).
5. Откройте историю (`1`) и статистику (`9`), затем
   завершите работу пунктом `0`.
6. Снова выполните `python main.py --data-dir .\local-data`: место, поездка и
   посещение остаются в SQLite. Через `7` можно изменить отметку, через `12` -
   поездку. Удаление поездки через `13` возможно только после удаления или
   переноса всех ее посещений.
