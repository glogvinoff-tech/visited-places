Visited Places - учебный сайт для учета мест, поездок и личных посещений.
Текущий этап: ПР7 «Основы баз данных и SQL».

## Запуск

В PowerShell из папки проекта при первом запуске:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.txt
.\venv\Scripts\python.exe manage.py init_db
.\venv\Scripts\python.exe manage.py runserver 127.0.0.1:8002
```

Откройте http://127.0.0.1:8002/. Остановка: `Ctrl+C`.
Если порт занят, замените `8002` на `8003` в команде и адресе браузера.
Для уже подготовленного проекта нужна только последняя команда.

`init_db` создает таблицы и переносит JSON только в пустую базу. При первичной
подготовке выводится случайный пароль учебного администратора `gleb`.
Повторный запуск не очищает данные и не изменяет пароль. В существующей
установке сохранены прежние пользователи и хеши их паролей.

Для сайта не нужны `migrate`, `collectstatic`, `django-admin` и `serve.py`.
Обычный `runserver` показывает адрес запуска и автоматически подхватывает правки.

## Возможности

- Регистрация, вход, выход, изменение имени/email.
- Просмотр, поиск и отдельные страницы мест, поездок и посещений.
- Создание записей, редактирование, удаление с подтверждением.
- Личный журнал с фильтрами по поездке и датам.
- Каталог непосещенных пользователем мест и поиск поездок на выбранную дату.
- Статистика по местам и странам, средняя оценка, порог числа посещений.
- Постраничный вывод через `LIMIT` и `OFFSET`.

Связи: `users -> visits -> trips -> places`. У поездки нет пользователя,
у посещения нет отдельного места. Дата посещения входит в период поездки,
оценка равна 1-5 или отсутствует. Связанные места и поездки нельзя удалять.

Любой вошедший пользователь может добавить место и поездку. Изменять и удалять
общий каталог может администратор. Свои посещения изменяет их владелец;
даже администратор не видит чужие отметки через страницы журнала.

## Структура

```text
config/settings.py                     настройки Django
config/urls.py                         корневые маршруты и handler404
visited_places/urls.py                 адреса страниц
visited_places/views.py                SQL, обработка форм и render()
visited_places/forms.py                поля и проверка значений
visited_places/auth.py                 текущий пользователь и проверка доступа
visited_places/templates/              страницы и общие фрагменты
visited_places/static/                 CSS, небольшой JS, фото и иконки
db/database.py                         подключение, чтение и запись SQLite
db/import_json.py                      перенос четырех JSON-файлов
sql/schema.sql                         CREATE TABLE и индексы
sql/queries.sql                        12 запросов с комментариями
data/visited_places.sqlite3            текущая база сайта
```

Путь данных: URL -> view -> SQL -> sqlite3.Row -> context -> Django-шаблон.
Поля читаются по имени: `place['name']` в Python, `{{ place.name }}` в шаблоне.
Значения передаются через `?`, не вставляются в SQL f-строками. Конкатенация
в представлениях соединяет только постоянные части запросов.

В `db/database.py` функции `fetch_all`, `fetch_one`, `execute` закрывают
соединение после операции; запись выполняет `commit()`. Сам SQL виден в views.
API и JavaScript-модалки заменены обычными страницами и POST-формами.
JavaScript нужен только для иконок и замены не загрузившейся фотографии.
Добавление, поиск, редактирование и удаление работают и без JavaScript.

## База ПР7

| Таблица | Основные поля |
| --- | --- |
| `users` | `id INTEGER PRIMARY KEY`; `username`, `name`, `email`, `password` TEXT; `is_staff`, `is_active` INTEGER |
| `places` | `id INTEGER PRIMARY KEY`; `name`, `city`, `country`, `category`, `image_url` TEXT |
| `trips` | `id INTEGER PRIMARY KEY`; `place_id INTEGER`; `name`, `start_date`, `end_date` TEXT |
| `visits` | `id INTEGER PRIMARY KEY`; `user_id`, `trip_id` INTEGER; `visited_at` TEXT; `rating` INTEGER или NULL; `note` TEXT |

Внешние ключи: `trips.place_id -> places.id`, `visits.user_id -> users.id`,
`visits.trip_id -> trips.id`. Соединения включают `PRAGMA foreign_keys = ON`.
Даты записываются в ISO-формате, время - местное московское, с точностью до минуты.
Данные проверяют формы, связи и основные ограничения дополнительно проверяет SQLite.

Отдельный перенос исходных JSON:

```powershell
.\venv\Scripts\python.exe -m db.import_json
```

`executemany()` переносит четыре коллекции в одной транзакции. При ошибке перенос
откатывается. Существующие записи и исходные JSON не перезаписываются.

В `sql/queries.sql` есть списки, `WHERE`, `JOIN`, `COUNT`, `AVG`, `GROUP BY`,
`HAVING`, `NOT EXISTS`, `LIMIT/OFFSET`. Эти виды запросов работают на страницах
сайта. Примеры с `user_id=1` можно заменить своим идентификатором.

В Python 3.12+ есть SQLite CLI, отдельный `sqlite3.exe` не обязателен:

```powershell
.\venv\Scripts\python.exe -m sqlite3 data/visited_places.sqlite3 "SELECT name, city FROM places;"
.\venv\Scripts\python.exe -m sqlite3 data/visited_places.sqlite3
```

Для поиска по русским словам подключение регистрирует небольшую SQL-функцию
`casefold`. Примеры из `queries.sql` используют стандартный SQL и работают
в обычном SQLite CLI без этой дополнительной функции.

## Предыдущие этапы и ограничения

Консоль запускается через `python main.py` и использует `data/journal.sqlite3`.
Классы в `users.py`, `places.py`, `trips.py`, `visits.py` и JSON сохранены для
сравнения с SQL-реализацией. Консоль и сайт имеют отдельные базы без синхронизации.

Старый `data/web.sqlite3` не изменялся и больше не используется сайтом.
Его записи и хеши паролей перенесены в новую базу, исходный файл оставлен
как резервная копия. Код до упрощения сохранен в Git: контрольная точка `b7e6c43`.
`REPORT_PR1.md`-`REPORT_PR6.md` описывают прошлые этапы, включая прежние ORM/API,
а не устройство текущей версии.

Сайт рассчитан на локальный запуск. Вход использует сессии Django с подписанными
cookies и стандартные хеши паролей Django. Cookies подписаны, но не зашифрованы;
в них хранится только идентификатор входа. Изменения защищены CSRF, тексты
экранируются шаблонами. Для публикации нужны собственный SECRET_KEY, HTTPS,
Secure cookies и серверное хранение сессий. Внешняя публикация не выполнялась.

Для своей страницы 404 можно локально задать `$env:DJANGO_DEBUG='0'`.
В этом случае для локальной статики добавьте к `runserver` флаг `--insecure`;
это только учебный запуск на своем компьютере, не настройка публикации.
Для обычной работы используйте `$env:DJANGO_DEBUG='1'`. При включенной отладке
Django показывает диагностическую страницу 404.
