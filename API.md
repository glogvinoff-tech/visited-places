## Аутентификация

Базовый адрес локального сервера: `http://127.0.0.1:8000`.
API доступен только после входа на `/login/` или регистрации на `/register/`.
Используется сессия Django; выход выполняется POST-запросом на `/logout/`.
Токены API, выбор чужого пользователя и передача пароля в URL не поддерживаются.

Изменяющие запросы требуют `Content-Type: application/json` и заголовок
`X-CSRFToken`. Интерфейс получает CSRF-токен из `meta[name="csrf-token"]`
страницы и отправляет cookie сессии через `credentials: "same-origin"`.
Обычный GET не изменяет записи.

## Адреса

| Адрес | Методы | Назначение |
| --- | --- | --- |
| `/api/me/` | GET, PATCH | Свой профиль: имя и email |
| `/api/places/` | GET, POST | Общий каталог мест |
| `/api/places/{id}/` | GET, PATCH, DELETE | Одно место |
| `/api/trips/` | GET, POST | Общие поездки |
| `/api/trips/{id}/` | GET, PATCH, DELETE | Одна поездка |
| `/api/visits/` | GET, POST | Только свои посещения |
| `/api/visits/{id}/` | GET, PATCH, DELETE | Только свое посещение |
| `/api/statistics/` | GET | Персональная статистика |

Места и поездки доступны для чтения/создания всем вошедшим пользователям.
PATCH/DELETE общего каталога требуют `is_staff`. Посещения доступны только
владельцу, в том числе при входе администратора в обычный интерфейс API.
Административный интерфейс Django имеет отдельные права.

PATCH частичный: не переданные поля сохраняются. Недоступные/неизвестные поля
отклоняются. Идентификаторы связей и оценка передаются JSON-числами,
не строками. DELETE возвращает `{"deleted": true}` с кодом 200.

В ответах места, поездки и посещения поле `url` содержит адрес соответствующей
HTML-страницы; оно доступно только для чтения. URL формируется через именованный
маршрут с пространством имён `visited_places`.

### Место

POST `/api/places/`:

```json
{
  "name": "Парк Победы",
  "city": "Калининград",
  "country": "Россия",
  "category": "Парк",
  "image_url": ""
}
```

Обязательны название, город, страна и категория. Фото необязательно;
допускаются только HTTP/HTTPS URL. Ответ дополняется `id`, `image` и `credit`.
`image` может ссылаться на локальную фотографию из учебного набора,
`credit` содержит ее источник и лицензию. Эти поля доступны только для чтения.
Внешние фотографии загружает браузер, сервер не скачивает адрес из формы.

### Поездка

POST `/api/trips/`:

```json
{
  "place": 7,
  "name": "Калининград",
  "start_date": "2026-10-12",
  "end_date": "2026-10-14"
}
```

Все поля обязательны. `place` - ID существующего места; в ответе это вложенный
объект места. У поездки нет пользователя. Начало не позже окончания.
При изменении дат учитываются все существующие отметки этой поездки.
Списки возвращают `visit_count`: число своих отметок, для администратора -
общее число отметок. Такое же правило применяется в ответе отдельной поездки.

### Посещение

POST `/api/visits/`:

```json
{
  "trip": 7,
  "visited_at": "2026-10-13T12:00",
  "rating": 5,
  "note": "Прогулка по парку"
}
```

Обязательны `trip` и `visited_at`. Время без смещения считается московским
(`Europe/Moscow`); ответ также использует московское время. `rating` -
целое 1-5 или `null`, `note` - до 2000 символов, по умолчанию пустая строка.
В ответе `trip` - вложенная поездка с местом. Поля `user` и `place` отсутствуют
в форме: пользователь берется из сессии, место определяется через поездку.
Дата должна попадать в период поездки. Повтор одной отметки того же пользователя,
поездки и момента времени запрещен.

### Профиль и статистика

PATCH `/api/me/` принимает только `name` и `email`. Email нормализуется
и должен быть уникальным; изменение привилегий через профиль невозможно.

`/api/statistics/` возвращает `visits`, `visited_places`, `cities`, `countries`,
`trips`, `average_rating`, `by_country`, `top_places`. Средняя оценка исключает
отметки без рейтинга и равна `null`, если оценок нет. Города различаются по
паре город/страна. Страны группируются без учета регистра; `top_places`
различает места по ID и содержит название, город, страну и число отметок.
Кеш разделен по пользователям, TTL 60 секунд; изменения
посещений сбрасывают кеш владельца после commit, изменения общих мест/поездок
сбрасывают кеш статистики целиком.

## Списки и ошибки

GET списков принимает `page` (от 1), `page_size` (1-200, по умолчанию 12),
`q` (поиск). Посещения дополнительно поддерживают `trip` (ID), `from` и `to`
(включительные даты `YYYY-MM-DD`).

```json
{"results": [], "count": 0, "page": 1, "pages": 1, "page_size": 12}
```

Для пустого результата существует первая страница. Выход за диапазон страниц
возвращает 400. Списки мест упорядочены по названию/ID, поездок - по началу/ID
по убыванию, посещений - по времени/ID по убыванию.

Поиск по названиям поездок и русским заметкам использует Python `casefold`
после отбора доступных записей, чтобы не зависеть от ASCII-сравнения SQLite.
При таком поиске подходящие записи читаются до пагинации: это решение
для небольшого учебного журнала, не полнотекстовый поиск большой базы.

HTML-списки используют те же выборки, пагинацию и расчет статистики,
что и API. Параметры GET-формы сохраняются при переходе по страницам,
включая `page_size`. Первоначальные записи выводятся Django-шаблонами;
для просмотра не требуется отдельный запрос API после загрузки страницы.

| Код | Значение |
| --- | --- |
| 200 / 201 | Успех / запись создана |
| 400 | Неверные поля, JSON, дата, дубликат при валидации или параметры |
| 401 | Нет действующей сессии |
| 403 | Нет прав или CSRF-токена |
| 404 | Запись отсутствует либо принадлежит другому пользователю |
| 405 | Метод не поддерживается |
| 409 | Связанные записи препятствуют удалению либо конфликт БД |

Ошибки имеют вид `{"error": "Сообщение", "errors": {"поле": ["Причина"]}}`.
`errors` необязателен. Ошибки входа/регистрации отображаются HTML-формами;
после 10 неудачных входов для пары IP/логин сервер возвращает 429 на пять минут.

## Схема базы данных

Веб-база - `data/web.sqlite3`, схема задается `0001_initial.py` и управляется
миграциями Django. Таблицы предметной области:

| Таблица | Основные поля и логические типы |
| --- | --- |
| `visited_places_user` | `id` PK INTEGER, `username` VARCHAR(150) UNIQUE, `name` VARCHAR(150), `email` VARCHAR(254) UNIQUE, `password` VARCHAR(128), признаки активности/прав и стандартные поля Django |
| `visited_places_place` | `id` PK INTEGER, `name` VARCHAR(160), `city`/`country` VARCHAR(100), `category` VARCHAR(60), `image_url` VARCHAR(500), служебные нормализованные ключи |
| `visited_places_trip` | `id` PK INTEGER, `place_id` FK NOT NULL, `name` VARCHAR(160), `start_date`/`end_date` DATE |
| `visited_places_visit` | `id` PK INTEGER, `user_id`/`trip_id` FK NOT NULL, `visited_at` DATETIME, `rating` SMALLINT NULL, `note` TEXT |

SQLite хранит даты/время в своем поддерживаемом представлении, а ограничение
длины VARCHAR проверяет модель/форма Django, не сам SQLite. Для сессий,
прав, групп и журнала административных действий используются стандартные
таблицы Django. Пароли содержат хеш, не открытый текст.

Кардинальности: один пользователь имеет много посещений; одна поездка имеет
много посещений; одно место имеет много поездок. Удаление пользователя удаляет
его отметки, но не общий каталог; удаление используемых места/поездки защищено
`PROTECT`. Проверки БД: email не пустой, даты поездки упорядочены,
оценка NULL или 1-5. Уникальны нормализованное место (название/город/страна)
и отметка (пользователь/поездка/время).

Индексы: внешние ключи, уникальные ограничения, место (город/страна), поездка
(место/даты), посещение (пользователь/время по убыванию). Это ускоряет выборки
по связям и личной истории; поиск подстроки не становится индексным только
из-за наличия этих индексов. `select_related` исключает отдельный запрос
для каждой строки, пагинация ограничивает объем ответа, статистика использует
агрегации ORM. Нагрузочная команда описана в README.

Данные пользователя/места не копируются в посещение: основные связи
нормализованы. Единственная служебная избыточность каталога - `*_key` для
Unicode `casefold`, чтобы кириллица сравнивалась без учета регистра;
они обновляются при сохранении модели. Статистика хранится только в кеше,
не дублируется в таблицах. Ручные SQL UPDATE и bulk update, обходящие
модельные проверки дат посещения и заполнение ключей, не являются поддерживаемым
способом редактирования данных приложения.

SQLite не шифруется приложением. Для локальной учебной установки используются
файловые права ОС, хеширование паролей, сессии и CSRF. Внешнее размещение
требует HTTPS, собственных секретов, ограниченного доступа к БД и резервным
копиям; детали настроек и ограничения одного процесса приведены в README.
