Цель ПР6 - продолжить развитие веб-приложения и реализовать отображение

шаблонную архитектуру на примере Roomly. Его приемы адаптированы
к теме Visited Places без замены сущностей и рабочего хранилища.

## Исходное состояние

На предыдущих этапах были реализованы:

- консольная модель `User`, `Place`, `Trip`, `Visit` и 167 тестов;
- Django-проект `config` и приложение `visited_places`;
- ORM-модели, миграции и отдельная SQLite-база `data/web.sqlite3`;
- регистрация, вход, сессии и разграничение прав;
- JSON API для мест, поездок, отметок и статистики;
- браузерный интерфейс и 40 веб-тестов.

Шаблон уже задавал каркас интерфейса, но списки и статистика первоначально
загружались и формировались клиентским JavaScript. В ПР6 реальные записи
перенесены в серверный HTML-ответ, а API сохранен для пользовательских
изменений и асинхронного обновления.

Связи предметной области не менялись: `User -> Visit -> Trip -> Place`.
У поездки нет пользователя, у отметки нет самостоятельного места.
Новые Django-модели и изменения схемы БД для ПР6 не потребовались.

Шаблоны находятся внутри Django-приложения и обнаруживаются через
`APP_DIRS=True`. Отдельный общий каталог шаблонов в `DIRS` не нужен.

`base.html` содержит структуру HTML, метаданные и подключение статических
ресурсов. `app.html` наследует его, определяет рабочую оболочку
с навигацией и подключает соответствующую часть содержимого.
Формы входа и регистрации также используют общий базовый шаблон.

Повторяющиеся фото, ячейка места, кнопки действий и пустые состояния
вынесены в отдельные части. Навигация подключается через `include`
из `navigation.html`. Python-представления не собирают HTML-строки.

## Контекст и отображение данных

Представления находятся в `visited_places/views.py`.
Функция `application()` получает доступные текущему пользователю записи,
вызывает общую пагинацию и передает контекст в `render()`.

Основные элементы контекста:

| Значение | Назначение |
| --- | --- |
| `view`, `title` | Текущий раздел и заголовок |
| `records` | Подготовленные записи текущей страницы |
| `stats` | Персональная статистика |
| `filters` | Значения поиска, поездки и дат |
| `trip_choices` | Варианты поездки для фильтра |
| `content_template` | Часть содержимого выбранного раздела |
| `initial_data` | Данные страницы для клиентской логики |
| `record`, `detail_record`, `list_url` | Отдельный объект и возврат к списку |

Применяются:

- `extends` и `block` для наследования общей структуры;
- `include` для повторяющихся фрагментов;
- `for` для списков записей, стран и вариантов поездок;
- `if` для прав администратора, отсутствующей оценки, фотографии
  и пустого списка;
- `url` для именованных переходов;
- `static` для CSS, JavaScript, фотографий и иконок.

Для даты и времени добавлены фильтры `journal_date` и `journal_time`.
Они форматируют реальные значения, учитывают московский часовой пояс
и не ломают шаблон при пустой или некорректной дате. Дополнительно
используются `default`, `floatformat`, `add`, `stringformat` и `widthratio`.

## URL и страницы объектов

В `visited_places/urls.py` задано `app_name = "visited_places"`.
Ссылки используют пространство имён, например:

```django
{% url 'visited_places:journal' %}
{% url 'visited_places:place-detail' record.id %}
```

Страницы проекта:

| Адрес | Назначение |
| --- | --- |
| `/` и `/visits/` | Личный журнал |
| `/places/` | Каталог мест |
| `/places/<id>/` | Сведения о конкретном месте и фотография |
| `/trips/` | Общий список поездок |
| `/trips/<id>/` | Место, период и число отметок поездки |
| `/visits/<id>/` | Свое посещение, дата, оценка и полная заметка |
| `/statistics/` | Персональная статистика |
| `/login/`, `/register/` | Вход и регистрация |

Для динамических адресов используется конвертер `int`.
Функция `detail()` находит объект и передает его в общий шаблон
отдельного объекта. Между отметкой, поездкой и местом есть переходы;
с отдельной страницы можно вернуться к списку.

Отсутствующая запись и чужая отметка возвращают оформленный ответ 404.
В production для неизвестного URL зарегистрирован `handler404`.
При DEBUG=True Django сохраняет диагностическую страницу неизвестного
маршрута; страницы отсутствующих объектов оформляются приложением.

## Интеграция с API

HTML и JSON используют общие функции `place_records`, `trip_records`,
`visit_records`, `page_data` и `statistics_data` из `api.py`.
Это сохраняет одинаковые фильтры, сортировку, пагинацию и правила доступа
для двух способов отображения данных.

Первоначальная страница не требует дополнительных запросов API для вывода
списка и статистики. Через `json_script` клиент получает уже подготовленные
данные без возможности внедрить HTML-код в элемент script.

GET-форма позволяет искать и фильтровать записи и переходить по страницам
без JavaScript. При включенном JavaScript формы редактирования
и подтверждения удаления используют API. На странице отдельного объекта
сохранение обновляет страницу, а удаление возвращает к списку.

Ответы API дополняются полем `url` с адресом HTML-страницы.
Идентификаторы, `url` и привилегии нельзя изменять через формы.
В пагинации возвращается `page_size`, чтобы сохранять выбранный размер
страницы. Контракт API описан в `API.md`.

## Безопасность и оптимизация

Требование входа, фильтрация отметок по `request.user`, права изменения
общего каталога и CSRF-защита сохранены. Даже администратор в обычном
HTML-интерфейсе и API не получает чужую личную отметку; административный
интерфейс Django имеет отдельные разрешения.

Пользовательские названия и заметки экранируются Django. На клиенте
текст выводится через `textContent`. Сервер проверяет поля, даты,
связи, ограничения рейтинга и защищенное удаление.

Сохранены `select_related`, индексы БД, пагинация и кеш статистики
на 60 секунд. Сброс кеша выполняется после commit. Начальный HTML
уже содержит данные, поэтому не возникает пустого списка до первого
ответа API. Фото загружаются лениво, при ошибке показывается заменяющая
иконка. CSS, JavaScript, изображения и библиотека иконок локальные.

SQLite и локальный кеш рассчитаны на небольшую установку с одним
процессом сервера. Поиск по русским заметкам и названиям поездок использует
Python `casefold`; для большого объема требуется иной текстовый поиск.
HTTPS, шифрование SQLite и автоматические резервные копии не добавлялись.

## Сравнение с примером Roomly

Предоставленные PDF являются подробными учебными материалами
с примером Roomly, а не сведениями о фактической реализации отдельного
студента. Сравнение проводится по подходу и демонстрируемым возможностям.

| Критерий | Пример из PDF | Visited Places |
| --- | --- | --- |
| Предметная область | Пользователи, помещения, бронирования | Пользователи, места, поездки, отметки |
| Framework | Django | Django |
| Проект и приложения | Проект Roomly, несколько тематических приложений | Проект `config`, одно небольшое приложение `visited_places` |
| Маршруты | Главная, списки, отдельные объекты, 404 | Журнал, списки, отдельные объекты, 404 |
| Шаблоны ПР6 | base, extends/block/include, контекст, for/if | Все перечисленные приемы применены |
| Именованные URL | Namespace отдельных приложений | Namespace `visited_places` |
| Статика | Собственные CSS/JS/изображения, пример Bootstrap | Собственные CSS/JS, локальные фотографии и Lucide |
| Хранилище на этапе ПР5-ПР6 | JSON и обычные Python-объекты, ORM отложен | Сохранены исходные классы/JSON; веб-часть уже использует SQLite и ORM |
| Изменение данных и защита | Авторизация, Forms и ORM не требуются на данном этапе примера | Уже реализованы по общей методичке предыдущих работ |

Основные принципы веб-части похожи. Сущности Roomly, названия приложений
и бизнес-правила бронирования не копировались. Наш проект не является
точным повторением пошагового плана PDF: главное различие - более раннее
использование ORM/SQLite и авторизации. Рабочая база не заменяется JSON
ради совпадения с примером; исходная консольная версия продолжает работать.

Django-шаблонов. Общая структура и повторяющиеся элементы вынесены

Добавлены страницы места, поездки и своей отметки с навигацией,
сохранены API, редактирование, проверки прав и предыдущая консольная
версия. Автоматические и браузерные проверки подтверждают работоспособность.
